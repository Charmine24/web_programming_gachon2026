useEffect Cheat Sheet

Everything from this week on one page: the patterns to copy and the mistakes to avoid.

Run once (on mount)

useEffect(() => {
  // setup
}, []);

Run on dependency change

useEffect(() => {
  fetchData(id);
}, [id]);

With cleanup

useEffect(() => {
  const id = setInterval(fn, 1000);
  return () => clearInterval(id);
}, []);

Async data fetch

useEffect(() => {
  async function load() {
    const d = await fetch(url).then(r => r.json());
    setData(d);
  }
  load();
}, [url]);

Loading pattern

const [data, setData]       = useState(null);
const [loading, setLoading] = useState(true);
const [error, setError]     = useState(null);

Dependency array rules

[]    → once on mount
[a]   → when a changes
none  → every render (avoid)

Avoid the infinite loop

// ❌ effect updates state that is in its deps
useEffect(() => { setX(x + 1); }, [x]);
// ✅ empty deps + functional update
useEffect(() => { setX(c => c + 1); }, []);

No async callback

// ❌ useEffect(async () => {...});
// ✅ define the async function inside
useEffect(() => {
  async function load() { /* ... */ }
  load();
}, []);

Cancel stale requests

useEffect(() => {
  const controller = new AbortController();
  fetch(url, { signal: controller.signal });
  return () => controller.abort();
}, [url]);

You might not need an effect

// ❌ extra state + extra render
useEffect(() => setFull(first + ' ' + last),
  [first, last]);
// ✅ derive it while rendering
const full = first + ' ' + last;

Self-check

  1. Can I explain what a side effect is and why it can't go in the render body?
  2. Can I choose the right dependency array for "once", "when X changes" and "every render"?
  3. Do all my timers, listeners and requests have a cleanup function?
  4. Does my fetch handle loading, errors (including !res.ok) and stale responses?
  5. Am I sure my effect does not update a state variable that is in its own dependency array?
