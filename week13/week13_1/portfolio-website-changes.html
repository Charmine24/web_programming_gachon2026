What changed

The contact section of the portfolio now has a message form. The portfolio remains a static HTML, CSS, and JavaScript site, so the Week 13 form patterns are implemented with framework-free JavaScript rather than adding a React build step.

1. Controlled inputs

The form collects a name, email, reason, source, message and consent. Following the Week 13 controlled-input pattern, js/main.js (section 7) handles the field values and validation in JavaScript instead of relying on the browser's default form submit (the form uses novalidate).

2. Select and textarea

An optional <select> asks how the visitor found the portfolio. The message <textarea> has a 500-character limit with a live 0 / 500 counter.

3. Radio buttons and a checkbox

Four radio buttons share name="reason" and store one string. A consent checkbox stores a boolean read from checked.

4. Validation and a disabled submit

Name, email, reason, message and consent are required (marked *), and each has its own error message slot under the field. The ./send_message button starts disabled, with a hint, until every required field is filled in.

5. Conditional rendering

After a successful submit the form is replaced by a success panel that greets the visitor by name, opens their email app with the message ready to send, and offers ./send_another.

6. Accessibility

Every field has a <label> or <legend>; error messages are linked with aria-describedby and announced through aria-live; the success panel uses role="status".

7. Files changed

index.html adds the form inside <section id="contact">. js/main.js (section 7) adds the form logic. css/style.css (section 12) styles the terminal-themed form.

Form markup added to index.html

Placed inside <section id="contact">, directly after the closing </div> of <div class="contact-list"> (the LinkedIn and Mail links).
